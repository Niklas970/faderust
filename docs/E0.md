# E0 – Prototyp: Mikrofon auf Bluetooth

Ziel: Herausfinden, wie groß Latenz und Takt-Drift zwischen einem USB-Mikrofon und einem Bluetooth-Ausgang sind. Davon hängen Puffergröße und Resampler-Regelung in E1 ab.

## Starten

```sh
# Geräte anzeigen
cargo run --release -p faderust-engine --example e0_passthrough -- --list

# 30 Minuten messen, Namen sind Teilstrings aus der Liste
cargo run --release -p faderust-engine --example e0_passthrough -- ^
    --input "USB" --output "Buds" --minutes 30 --buffer-ms 60 --csv e0.csv
```

Ohne `--input` / `--output` werden die Windows-Standardgeräte genommen. Kopfhörer aufsetzen, sonst gibt es Rückkopplung.

## Was gemessen wird

| Spalte | Bedeutung |
|---|---|
| `in[Hz]`, `out[Hz]` | Tatsächliche Abtastrate von Eingang und Ausgang, gemittelt seit Start |
| `drift` | Abweichung in ppm. Positiv heißt: das Mikrofon läuft schneller als der Ausgang |
| `fill` | Füllstand des Ringpuffers. Wandert er stetig, ist das die Drift |
| `in_lat`, `out_lat` | Von WASAPI gemeldete Gerätelatenz (Aufnahme bis Callback, Callback bis Wiedergabe) |
| `total` | Schätzung: `in_lat + fill + out_lat` |
| `dropped`, `underrun` | Verlorene bzw. mit Stille gefüllte Frames. Bei Unterlauf wartet die Wiedergabe, bis der Puffer wieder voll ist |

Es gibt absichtlich keinen Resampler. Ohne Ausgleich zeigt der Puffer, wie schnell die beiden Takte auseinanderlaufen: 100 ppm sind rund 0,36 s pro Stunde.

## Grenzen

- Die Bluetooth-Codec-Verzögerung (SBC/AAC, oft 100–200 ms) meldet WASAPI meist nicht. Die echte Ende-zu-Ende-Latenz am besten zusätzlich per Klatschtest messen: Handy-Aufnahme neben Mikro und Kopfhörer, Abstand der beiden Klatscher in Audacity ablesen.
- Weicht die Rate des Ausgabegeräts ab, rechnet Windows um (`AUTOCONVERTPCM`). Die Drift bleibt trotzdem sichtbar.
